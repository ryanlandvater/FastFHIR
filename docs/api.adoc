= FastFHIR — External API Reference

:toc: macro
:source-highlighter: highlight.js

This document is the reference for FastFHIR's *external* surface across all
three languages it ships. Each is a distinct, hand-written entry point over one
library:

* **C++** — the `FF_*` surface declared in `include/FastFHIR.hpp`. Every entry
  point is a free function that returns an `FF_Result`, is `noexcept`, and —
  except for the one templated append — takes a single `const FF_XxxInfo&`
  argument so the surface can grow by adding struct fields instead of changing
  signatures. The first sections below cover it.
* **C** — the pure-C ABI in `include/FastFHIR.h`, with opaque handles and
  `FF_ResultInfo`. See <<C ABI (`FastFHIR.h`)>>.
* **Python** — the `fastfhir` package (`python/`), a pybind11 binding over the
  C++ core plus a small Pythonic layer. See <<Python API>>.

All three share the same design conventions — one `const XxxInfo&`-shaped
parameter struct per call, handles rather than long argument lists, errors
returned rather than thrown across the boundary — so learning one teaches the
shape of the others.

> **Source of truth.** `include/FastFHIR.hpp` declares the C++ surface,
> `include/FastFHIR.h` the C surface, and `python/fastfhir/__init__.py` (with the
> `_core` extension) the Python surface. Keeping this page in sync by hand is
> tracked in TASKS.md, *"WORK ORDER — FF_* EXTERNAL API: asciidoc generation +
> README sweep"*; the goal is to generate the C++ portion from the header so it
> can never drift. Until then every claim here is hand-checked against the
> source, and the checks that were run are noted where they are not obvious.

== Design conventions

The surface follows the Iris/Vulkan shape:

* **Handles** are shared-ownership value types: `FF_Memory`, `FF_Builder`,
  `FF_Ingestor`. Copy them freely; they all refer to one underlying object.
* **Create/lifecycle functions** follow the Vulkan pattern: an Info struct in,
  a `T& out` parameter, an `FF_Result` out. Errors never throw — the
  implementation catches everything below this boundary.
* **Read/query returns** (`Parser`, `Memory::View`) are cheap value types.
  `Parser` is deliberately *not* a handle: it is a zero-copy, copyable value
  over a buffer, built with one of its two constructors (`Parser(buffer, size)`
  or `Parser(memory)`).
* **The mutation path is unchanged**: once an object is appended, fields are
  written with the reflective handle (`handle[key] = value`), exactly as before.
  String values are assigned as `std::string_view`; see the Builder API section.

`FASTFHIR_VERSION_*` macros.

== Handles

```cpp
using FF_Memory   = FastFHIR::Memory;   // copyable arena handle (owns a Memory_t)
using FF_Builder  = FastFHIR::Builder;  // = std::shared_ptr<Builder_t>
using FF_Ingestor = FastFHIR::Ingestor; // = std::shared_ptr<Ingestor_t>
```

`FastFHIR::Ingestor_t` is deliberately opaque in the installed header — its definition
lives in the internal `FF_Ingestor.hpp` so consumers never see simdjson/WAMR.

== Result type

The result types are declared in `namespace FastFHIR` and reachable globally as
`FF_Result` / `FF_Result_Code` / `FF_Result_Severity` (the `FF_` spelling of the
namespace, per the type-naming rule). The status-code enumerators
(`FF_SUCCESS`, `FF_FAILURE`, …) stay reachable unqualified.

```cpp
enum class Result_Severity : uint8_t { SUCCESS, WARNING, FAILURE };

enum Result_Code : uint32_t {
    // success
    FF_SUCCESS = 0,
    // warnings — operator bool is TRUE; inspect code/message to see them
    FF_WARNING_PARTIAL_INGEST  = 1,  // some resources discarded (out-of-profile)
    FF_WARNING_LOGGER_OVERFLOW = 2,  // warning buffer truncated
    FF_WARNING_EMPTY_RESULT    = 3,  // succeeded but produced no output
    // failures — operator bool is FALSE. Banded at 0x100 so severity is legible
    // from the value alone, and so a warning can be added later without
    // renumbering any failure.
    FF_FAILURE            = 0x100, // generic engine failure
    FF_VALIDATION_FAILURE = 0x101, // stream/offset/type validation failed
    FF_INVALID_ARGUMENT   = 0x102, // null handle, mutually exclusive fields
    FF_CAPACITY_EXCEEDED  = 0x103, // arena or buffer capacity exceeded
    FF_IO_FAILURE         = 0x104, // file/network I/O failure
    FF_NOT_IMPLEMENTED    = 0x105, // HL7 v2/v3 ingestion, etc.
    FF_EXTENSION_FAILURE  = 0x106, // WASM extension codec failure
};

struct Result {
    Result_Code code;
    std::string message;   // newline-stacked, severity-tagged entries
    // Construction. The one-argument form is NOT explicit, so `return
    // FF_SUCCESS;` compiles. There is no default constructor.
    Result(Result_Code c, std::string msg); // tags msg by severity
    Result(Result_Code c);                  // empty message
    // severity_of(code) is the single classification source
    bool succeeded() const noexcept;  // true for SUCCESS and WARNING
    bool is_warning() const noexcept; // true only for WARNING codes
    bool failed() const noexcept;     // true only for FAILURE codes
    operator bool() const noexcept;   // == succeeded()
    // message construction
    Result& append(Result_Code c, std::string msg); // one tagged entry per line
    Result& append(const Result& other);            // merge; most severe code wins
};
```

Every `FF_*` function returns an `FF_Result`. The severity model is:

* **`succeeded()` / `operator bool`** is true for *both* success and warnings —
  a run that produced usable output but dropped something along the way is
  not a failure, and a caller that only cares about go/no-go can write
  `if (!result) return;` and ignore warnings entirely.
* **Warnings still exist — they stack.** `FF_Result::message` is a
  newline-separated stack of tagged entries: `[WARNING] ...` for warning codes
  and `[FATAL] ...` for failure codes. Every entry point prefixes its first
  entry with the code's tag; producers accumulate more entries with
  `append()`. `FF_Ingest`, for example, stacks one `[WARNING]` entry for the
  aggregated out-of-profile discard summary plus one per engine `[Warning]`
  log line (malformed data, skipped fields) — none of it is lost.
* **Errors are `[FATAL]`.** Failure results tag their message
  `[FATAL] ...`; when a fatal lands after warnings, `append()` promotes the
  code (failure > warning > success) and both kinds of entries stay in the
  message.
* **Failures** (`failed()`) are the only results that convert to `false`.
  Input errors return `FF_INVALID_ARGUMENT`; stream/offset/type checks return
  `FF_VALIDATION_FAILURE`.

Unknown codes classify as `FAILURE` — a stale or typo'd code fails safe.

```cpp
using FF_HashCallback = std::function<std::vector<BYTE>(const unsigned char* byte_start, Size bytes_to_hash)>;
```

Required when the chosen algorithm is not `FF_CHECKSUM_NONE`.

== Memory (arena) API

```cpp
struct FF_MemoryCreateInfo {
    Size        capacity = 4 GiB;   // sparse virtual reservation
    const char* shm_name = nullptr; // cross-process SHM name; null = anonymous RAM
    const char* filepath = nullptr; // file-backed arena; exclusive with shm_name
};

FF_Result FF_CreateMemory(const FF_MemoryCreateInfo& info, FF_Memory& out_memory) noexcept;
FF_Result FF_MemoryReset(const FF_Memory& memory, Size committed_size) noexcept;
Size      FF_MemorySize(const FF_Memory& memory) noexcept;
Size      FF_MemoryCapacity(const FF_Memory& memory) noexcept;
```

* `FF_MemoryReset` with `committed_size = 0` before streaming raw serialized
  bytes into the arena so the first byte lands at offset 0.
* Raw-arena access (network `StreamHead`, `claim_space`) remains available
  through the underlying `Memory` value type.

== Builder API

```cpp
struct FF_BuilderCreateInfo {
    Size        capacity = 4 GiB;   // sparse virtual reservation
    FHIR_VERSION version  = FHIR_VERSION_R5;
    FF_Memory   arena    = nullptr; // existing arena to build into; exclusive with filepath/shm_name
    const char* filepath = nullptr; // file-backed arena; exclusive with arena/shm_name
    const char* shm_name = nullptr; // cross-process SHM arena; exclusive with arena/filepath
};

FF_Result FF_CreateBuilder(const FF_BuilderCreateInfo& info, FF_Builder& out_builder) noexcept;

template <typename T_Data>
Reflective::ObjectHandle FF_BuilderAppendObject(FF_Builder builder, const T_Data& data) noexcept;

struct FF_BuilderSetRootInfo {
    FF_Builder               builder = nullptr;
    Reflective::ObjectHandle root;   // handle returned by FF_BuilderAppendObject
};

FF_Result FF_BuilderSetRoot(const FF_BuilderSetRootInfo& info) noexcept;

struct FF_BuilderFinalizeInfo {
    FF_Builder            builder   = nullptr;
    FF_Checksum_Algorithm algorithm = FF_CHECKSUM_NONE;
    FF_HashCallback       hasher    = nullptr;  // required when algorithm != NONE
};

FF_Result FF_BuilderFinalize(const FF_BuilderFinalizeInfo& info, Memory::View& out_view) noexcept;

struct FF_BuilderQueryInfo { FF_Builder builder = nullptr; };
FF_Result FF_BuilderQuery(const FF_BuilderQueryInfo& info, Parser& out_parser) noexcept;
```

`FF_BuilderAppendObject` is the one two-argument entry point: the payload is a
template parameter, so it cannot live in an Info struct without forcing a copy.
It returns a valid `ObjectHandle`, or a **null handle on failure** (never
throws). Once you have the handle, mutate fields with the reflective path:

```cpp
auto root = FastFHIR::FF_BuilderAppendObject(builder, obs);
root["status"] = std::string_view("final");                 // string key
root[FastFHIR::Fields::OBSERVATION::STATUS]                 // typed key, same field
    = std::string_view("final");
```

A string value must be a `std::string_view`, not a bare literal:
`MutableEntry::operator=` is a template over `T_Data` and instantiates
`TypeTraits<T_Data>`, which is undefined for `char[N]` — so `= "final"` fails to
compile with an *"implicit instantiation of undefined template
`TypeTraits<char[6]>`"* error rather than converting. Non-string values (`bool`,
arithmetic types, generated structs) need no wrapper.

The string key `"status"` works because `FF_FieldKey` has a non-explicit
constructor from a string literal, so it converts implicitly. It is the slower
path — it resolves by name — and it is unchecked against the owning resource:
the typed key carries its owner's `RECOVERY_TAG` and so cannot be pointed at the
wrong resource type by mistake. Prefer the typed key.

== Parse API

`Parser` is the read lens, and it is the one surface that is *not* an
`FF_*Info` struct. It is built directly with one of **two explicit
constructors**:

```cpp
Parser(const void* buffer, size_t size);  // bytes the caller already holds
Parser(const Memory& memory);             // an arena: openReadOnly() or a Builder's
```

The two forms are mutually exclusive by construction — you cannot supply both,
so there is no `FF_ParseInfo` and no runtime "buffer and memory are mutually
exclusive" check to run.

[cols="1,1,3"]
|===
| Form | Constructor | Use
| Raw bytes | `Parser(buffer, size)` | A socket read, a `std::vector`, any buffer the caller already owns
| Arena | `Parser(memory)` | `Memory::openReadOnly()` over a file, or the arena a `Builder` just wrote
|===

`Parser(memory)` keeps the arena handle, so the mapping lives exactly as long
as the parser does — that is what lets a reader mount a file read-only with no
copy of its bytes. Both validate the header and root offset only (see
`FF_Parser.hpp` for the trust model) and throw `FastFHIR Parsing Error: ...` on
a bad stream, including a null buffer or arena.

The C ABI has no constructors, so it mirrors the pair with two factories —
`FF_CreateParserFromBuffer(buffer, size, &out)` and
`FF_CreateParserFromMemory(memory, &out)`; see <<C ABI (`FastFHIR.h`)>>.

== Compact API

```cpp
struct FF_CompactInfo {
    Parser                source;    // parsed stream to archive
    FF_Checksum_Algorithm algorithm = FF_CHECKSUM_NONE;
    FF_HashCallback       hasher    = nullptr;
};

FF_Result FF_Compact(const FF_CompactInfo& info, Memory::View& out_view) noexcept;
```

The compact archive is written into a fresh arena sized from the source. That
sizing rests on the assumption that compaction never grows a stream — the dense
layout drops absent slots but adds a presence bitmask per block, so the
assumption is not self-evident and is not asserted anywhere. It fails **safely**
rather than silently: exceeding the arena throws inside `claim_space`, which
`FF_Compact` catches and returns as `FF_CAPACITY_EXCEEDED`. The source stream is
never modified.

== Ingest API

```cpp
enum FF_SourceType : uint8_t { FF_SOURCE_FHIR_JSON, FF_SOURCE_HL7_V2, FF_SOURCE_HL7_V3 };

struct FF_IngestorCreateInfo {
    Size     logger_capacity = 64 MiB; // lock-free warning buffer bytes
    uint32_t concurrency     = 0;      // worker threads; 0 = hardware concurrency
};

FF_Result FF_CreateIngestor(const FF_IngestorCreateInfo& info, FF_Ingestor& out_ingestor) noexcept;

struct FF_IngestInfo {
    FF_Ingestor           ingestor  = nullptr;
    FF_Builder            builder   = nullptr;  // destination builder
    FF_SourceType         source_type = FF_SOURCE_FHIR_JSON;
    const std::string_view payload;             // raw source document — never modified
    Size                  payload_capacity = 0; // allocated bytes incl. simdjson slack; 0 = safe copy
};

FF_Result FF_Ingest(const FF_IngestInfo& info,
                    Reflective::ObjectHandle& out_root,
                    Size& out_parsed_count) noexcept;

struct FF_IngestInsertInfo {
    FF_Ingestor              ingestor    = nullptr;
    Reflective::ObjectHandle parent;      // object being amended
    FF_FieldKey              key;         // target field within parent
    const std::string_view   payload;     // raw source document — never modified
    FF_SourceType            source_type = FF_SOURCE_FHIR_JSON;
};

FF_Result FF_IngestInsertAtField(const FF_IngestInsertInfo& info) noexcept;
```

* `payload` is a `const` view: the ingestor can never modify the caller's
  source bytes.
* Set `payload_capacity` to the real allocated size of your buffer (including
  `simdjson::SIMDJSON_PADDING` slack) to parse **in place with no copy**;
  leave 0 for a safe padded copy.
* `FF_Ingest` returns the inserted root as `out_root` and the number of
  top-level resources parsed as `out_parsed_count`.

== What is intentionally *not* part of this surface

* **`Builder::set_root` / `finalize` / `query`** — private; reachable only
  through the FF_* functions above.
* **`Builder::append_obj(const std::vector<Offset>&, RECOVERY_TAG)`** — still
  public on the `Builder` behind `FF_Builder`, and callable as
  `stream->append_obj(offsets, tag)`; it is what backs
  `MutableEntry::operator=(vector<Offset>)`. It has no `FF_*` wrapper, so it is
  outside the covered surface without being unreachable.
* **`Compactor::archive`** — internal; external callers use `FF_Compact`.
* **`Ingest::Ingestor` / `IngestRequest`** — internal; external callers use
  the FF_Ingest surface.
* **`FF_Queue`, `FF_SIMD`, `FF_Extensions`, `FF_Compactor`** — internal
  helpers, not in the install set.

=== Installed headers

The public header set is **derived once** in `CMakeLists.txt`
(`FASTFHIR_PUBLIC_HEADERS`): the named `include/` headers, `FastFHIR.hpp` and
`FastFHIR.h` among them, plus a filtered glob of `generated_src/FF_*.hpp` that
excludes the `*_internal.hpp` wire/view headers and the ingestor-only
`FF_IngestMappings.hpp` / `FF_KnownExtensions.hpp` / `FF_Conformance_Layer.hpp`.
So the installed POCO set is exactly the build profile's. `FF_Ops.hpp` (arena
byte arithmetic) is internal by design and is never installed — CLAUDE.md
invariant 9. `FF_TypeTraits.hpp` and `FF_Export.h` are installed because the
public headers include them.

The set is self-contained: `#include <FastFHIR.hpp>` and `#include <FastFHIR.h>`
both compile against an installed prefix. `tests/install/install_smoke.cmake`
(ctest `install_smoke`) installs to a scratch prefix and builds a
`find_package(FastFHIR CONFIG)` consumer against it only, asserting the public
headers are present and `FF_Ops.hpp`, `FF_AllTypes.hpp` and `*_internal.hpp`
are absent.

== C ABI (`FastFHIR.h`)

The surface documented above is C++. A **pure-C** surface — `include/FastFHIR.h`,
implemented by `src/FF_C_API.cpp` — lets a C program link `libfastfhir` with no
C++ compiler. It is a separate header, not a re-export: the C++ side keeps its
classes, references and templates, and the two name the same concepts with
different types. Neither includes the other, and **neither may be included
alongside the other in one translation unit**: the C `FF_MemoryCreateInfo` is
global while the C++ one is in `namespace FastFHIR`, so a single
`using namespace FastFHIR;` — which every example writes — makes the name
ambiguous and the translation unit stops compiling. Pick the surface the
translation unit needs.

The C surface uses **opaque handles** (`FF_MemoryHandle`, `FF_BuilderHandle`,
`FF_ParserHandle`, `FF_ViewHandle`, `FF_ObjectHandle`) and returns
`FF_ResultInfo` (`code`, `severity`, and a thread-local `message`). Every
factory has a matching `FF_Destroy*`; nothing throws across the boundary. Each
entry point takes a parameter struct (`const FF_XxxInfo*`) or a handle rather
than a long positional list, and each `FF_XxxInfo` mirrors its C++ twin field
for field. The one exception is the parse pair — `FF_CreateParserFromBuffer` /
`FF_CreateParserFromMemory` take positional arguments, because they are the two
`Parser` constructors and each needs at most three arguments, which is the
threshold the Info-struct rule exists to stay under. Two documented divergences
follow. The checksum `hasher` is a `std::function` the library calls back into,
so it cannot cross the ABI and the C `FF_BuilderFinalizeInfo` / `FF_CompactInfo`
stop one field short; the gate records that as `cpp_only` rather than letting
the two lists differ quietly. And there is no C `FF_ParseInfo`, because there is
no C++ one to mirror.

```cpp
using FF_Memory   = FastFHIR::Memory;   /* an opaque pointer in C */
struct FF_MemoryCreateInfo {            /* C twin in FastFHIR.h       */
    uint64_t    capacity;
    const char *shm_name;
    const char *filepath;
};
FF_ResultInfo FF_CreateMemory(const FF_MemoryCreateInfo *info, FF_MemoryHandle *out);
```

The shared facts — struct fields and their order, enum values — are held once in
`tests/generator/c_abi_spec.py` and checked against BOTH headers by
`tests/generator/test_c_abi.py`, so a field added to one and forgotten in the
other fails the gate by name. That is why the two `FF_MemoryCreateInfo`
definitions can coexist without drift even though neither includes the other.

== Python API

The `fastfhir` package (`python/`) is a pybind11 binding over the C++ core
(`_core`) plus a thin Pythonic layer in `fastfhir/__init__.py`. Import it as:

```python
import fastfhir as ff
```

It exposes the same three entry points as the C++ surface — a `Memory` arena, a
`Builder` that writes into it, and an `Ingestor` that parses FHIR JSON — with
Python naming (snake_case members) and Python value types in place of C++
structs. `.value()` and `.items()` return native `bool` / `int` / `float` /
`str` / `dict` / `list` where the C++ side returns a view or a block.

=== Enums

Enums live at the top level as nested classes, not bare constants:

[cols="1,2"]
|===
| `ff.FhirVersion` | `R4`, `R5`
| `ff.SourceType` | `FHIR_JSON`, `HL7_V2`, `HL7_V3`
| `ff.Checksum` | `NONE`, `CRC32`, `MD5`, `SHA256`
| `ff.ResourceType` | `Patient`, `Bundle`, `Observation`, `Encounter`, `DiagnosticReport`, …
|===

=== `ff.Memory`

The arena. `create` is anonymous RAM; `create_from_file` is file-backed and
appends to an existing sealed stream, exactly as it does in C++.

```python
mem = ff.Memory.create(capacity=4 * 1024**3)                       # anonymous RAM
mem = ff.Memory.create_from_file("data.ffhr", capacity=4 * 1024**3) # file-backed
```

[cols="1,1,3"]
|===
| Member | Returns | Notes
| `.capacity` | `int` | Bytes *reserved* (virtual address space), not committed pages
| `.size` | `int` | Bytes currently written
| `.name` | `str` | SHM name; empty for anonymous arenas
| `.view()` | `MemoryView` | Zero-copy buffer-protocol slice of the committed arena
| `.reset(committed_size=0)` | — | Rewind the write head; the mapping stays open
| `.try_acquire_stream()` | `StreamHead` | Exclusive raw-ingest cursor; use as a context manager and `.commit(n)`
| `.close()` | — | Release the mapping
|===

=== `ff.Builder`

A context manager that binds an arena and seals it on exit. `finalize` and
`compact` inject the standard-library hasher for `SHA256` / `MD5` / `CRC32`
automatically when none is given, so the common case needs no callback.

```python
with ff.Builder(mem, ff.FhirVersion.R5) as builder:
    ...
    view = builder.finalize(algo=ff.Checksum.SHA256)   # MemoryView over the sealed bytes
```

[cols="1,1,3"]
|===
| Member | Returns | Notes
| `.root` | `BuilderNode` | Root node
| `.version` | `FhirVersion` | R4 or R5
| `.root_type` | `ResourceType` | Resource kind at root
| `.to_json()` | `str` | Full stream JSON
| `.finalize(algo=NONE, hasher=None)` | `MemoryView` | Seal and write the checksum footer
| `.compact(algo=NONE, hasher=None)` | `MemoryView` | Compact the sealed stream into a fresh arena it allocates
| `.query()` | `Parser` | A read lens over the sealed bytes
| `.checksum` | `ChecksumValidation` | Footer metadata: payload start, byte count, algorithm, expected digest
| `.has_url_directory` / `.url_directory` | `bool` / `FF_URL_DIRECTORY` | The stream's interned extension-URL table
| `.has_module_registry` / `.module_registry` | `bool` / registry | WASM extension codecs; only in streams built with the extension host
|===

> `.checksum` reports what the footer *claims*. It is an **integrity** record,
> not an authenticity one — anyone who can rewrite the payload can recompute it.

=== `ff.Ingestor`

Parses a payload and appends the resulting resource(s) into a builder.

```python
ingestor = ff.Ingestor(concurrency=4)
node, count = ingestor.ingest(builder, ff.SourceType.FHIR_JSON, json_string)
# node  → BuilderNode at the root resource
# count → number of resources written
```

[cols="1,1,3"]
|===
| Member | Returns | Notes
| `.ingest(builder, source_type, payload)` | `(BuilderNode, int)` | Root node and the resource count written
| `.is_faulted` | `bool` | The engine hit an unrecoverable error and will refuse further work
| `.reset()` | `str` | Clear the fault and return the drained diagnostic log
|===

> A resource type outside the compiled `FASTFHIR_PRODUCTION_PROFILE` is **not
> dropped** — it is retained verbatim as opaque JSON and re-emitted byte-for-byte.
> What you lose is typed access; check the ingest warnings to see which types took
> that path. Same behaviour as the C++ `Builder::append_opaque_json`.

=== Field registry — `ff.<Type>.<FIELD>`

Fields are generated path objects, imported from `fastfhir.fields`. Type names
are PascalCase, field names SCREAMING_CASE, and array fields support integer
indexing to build deep paths:

```python
ff.Patient.ID                 # patient.id           (scalar)
ff.Patient.NAME               # patient.name         (array of HumanName)
ff.Patient.NAME[0].FAMILY     # patient.name[0].family (deep path)
ff.Bundle.ENTRY[0].RESOURCE   # bundle.entry[0].resource
ff.Observation.CODE           # CodeableConcept block
```

=== The read path — `BuilderNode` and `MutableEntry`

`node[ff.X.FIELD]` returns a `MutableEntry`; a block- or array-valued entry
yields a `BuilderNode` from `.value()`. Both support presence (`bool`), length
(`len`), iteration, `items()` (lazy) and `items(recursive=True)` (fully
materialized into native Python values), and `to_json()`.

```python
root   = builder.root
active = root[ff.Patient.ACTIVE].value()          # bool
name   = root[ff.Patient.NAME][0]                 # MutableEntry, array element
family = name[ff.HumanName.FAMILY].value()        # str
for key, entry in root.items():                   # present fields only
    print(key, entry.value())
```

=== Complete example

```python
import fastfhir as ff

mem      = ff.Memory.create(capacity=512 * 1024 * 1024)
ingestor = ff.Ingestor()

with open("patient.json") as f:
    payload = f.read()

with ff.Builder(mem, ff.FhirVersion.R5) as builder:
    root, _ = ingestor.ingest(builder, ff.SourceType.FHIR_JSON, payload)
    builder.finalize(algo=ff.Checksum.SHA256)

# Read it back through the same zero-copy lens.
with ff.Builder(mem, ff.FhirVersion.R5) as reader:
    node = reader.root
    print(node[ff.Patient.ID].value(), node[ff.Patient.GENDER].value())
```
